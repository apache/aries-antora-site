= RSA (Remote Service Admin)

The Aries Remote Service Admin (RSA) project allows regular OSGi services to be transparently accessed remotely.
OSGi services can be marked for export by adding the service property `service.exported.interfaces=*`.
Various other properties can be used to customize how the service is to be exposed.

For more information, see section 122 "Remote Service Admin Service Specification"
in the "OSGi Compendium Release 8" specification, available from the
https://docs.osgi.org/specification/osgi.cmpn/8.0.0/service.remoteserviceadmin.html[OSGi Working Group].

== Source

The Aries RSA source code is available on https://github.com/apache/aries-rsa[GitHub].

=== Some Definitions

* Export - the process of making a local service available for access by remote hosts.
* Import - the process of making a remote service available for access by local services,
  by creating a local proxy whose invocation is sent to the remote service behind the scenes.
* `EndpointDescription` - describes a remote service via a set of properties containing both the original
  service properties and all metadata needed to reach and use it remotely
  (e.g. the exported interfaces, URI, transport details, etc).
* `EndpointEventListener` - an interface implemented by services that are used either to notify
  (on the exporting side) or be notified about (on the importing side) remote endpoints that
  appear or disappear (filtered by scope as needed).

=== https://github.com/apache/aries-rsa/tree/master/topology-manager[Topology Manager]

The "brain" that manages imports and exports:

* Listens to local services and decides which to export and how to do so based on their properties.
  It calls `RemoteServiceAdmin.exportService` to perform the actual export,
  then notifies ``EndpointEventListener``s about the new endpoint.
* Listens for service lookup/tracking by consumers and creates ``EndpointEventListener``s to track these interests,
  so it can decide when a remotely exported service should be imported locally.

The default Topology Manager exposes all suitably marked local services for export
and imports all remote endpoints for which there are locally interested consumers.

Custom Topology Managers can be used to implement system-wide governance rules,
such as enhancing all exposed remote endpoints with SSL, basic auth, logging,
or exporting OSGi services with annotations for JAX-WS or JAX-RS even when
they are not explicitly marked for export.

=== https://github.com/apache/aries-rsa/tree/master/rsa[Remote Service Admin]

Does the "heavy lifting" of the actual exporting and importing. It is called by the Topology Manager
to expose local services as remotely accessible endpoints and to create local proxy services as clients for remote endpoints.

A distribution provider is the transport mechanism by which service
method invocations are sent to be executed remotely and the return values are sent back.
Aries RSA has a custom SPI `https://github.com/apache/aries-rsa/blob/master/spi/src/main/java/org/apache/aries/rsa/spi/DistributionProvider.java[DistributionProvider]`
that allows anyone to easily implement new transports and serializations in a pluggable manner.

Existing providers are:

* https://github.com/apache/aries-rsa/tree/master/provider/tcp[TCP]
 ** standard Java serialization over TCP
 ** very few dependencies
 ** multiplexing over a single port or separate port per service
 ** SSL/TLS
 ** easy to comprehend blueprint for custom transport implementations
* https://github.com/apache/aries-rsa/tree/master/provider/fastbin[Fastbin]
 ** optimized Java serialization (or Protobuf) over TCP using NIO
 ** multiplexing over a single port
 ** transparently handles ``InputSteam``s and ``OutputStream``s in remote services
 ** synchronous and asynchronous calls supported

=== Discovery

A discovery implementation is the mechanism for distributed delivery of notifications about endpoints.
It uses ``EndpointEventListener``s on the exporting side to listen for local
endpoints being created or destroyed and forwards those notifications to remote containers.
On the importing side it receives those remote notifications and notifies all interested local
``EndpointEventListener``s (such as Topology Managers) about these endpoint changes.

Existing implementations:

* https://github.com/apache/aries-rsa/tree/master/discovery/local[Local discovery]
  Scans bundles for XML endpoint descriptions and notifies local ``EndpointEventListener``s
  about the described endpoints so that they can be imported.
* https://github.com/apache/aries-rsa/tree/master/discovery/config[Config discovery]
  Tracks ConfigAdmin factory configurations and notifies local ``EndpointEventListener``s
  about the configured remote endpoints so that they can be imported.
* https://github.com/apache/aries-rsa/tree/master/discovery/TCP[TCP discovery]
  Opens direct TCP connections between every pair of pre-configured peers in a network
  and uses standard Java serialization to send endpoint notifications between them.
  A lightweight implementation for a small number of nodes.
* https://github.com/apache/aries-rsa/tree/master/discovery/zookeeper[ZooKeeper discovery]
  Uses a distributed ZooKeeper cluster as a registry where all endpoint changes in the
  network are tracked. Scales well in networks with a large number of nodes.
* https://github.com/apache/aries-rsa/tree/master/discovery/MDNS[MDNS discovery]
  Uses the mDNS multicast protocol to inform nodes in a local network about their
  peers, and then SSE over HTTP on each to send the endpoint data itself.

== A simple example using Apache Karaf

See https://github.com/apache/aries-rsa/tree/master/examples/echotcp[EchoTCP example].
Follow the Readme to install the example in Apache Karaf.

The EchoTCP example implements a simple echo service that can be called remotely.
The example uses declarative services to publish and bind services.

=== Modules

* api - the `EchoService` interface
* service - the `EchoService` implementation
* consumer - a small consumer that uses the `EchoService`

The example installation uses the TCP transport to do the remoting
but the example code is not tied to any specific transport.

== Example using Fastbin transport

A similar https://github.com/apache/aries-rsa/tree/master/examples/echofastbin[example]
exists for the Fastbin transport. Follow the Readme to install the example in Apache Karaf.

The example implements an echo service that showcases synchronous calls,
asynchronous calls and ``InputStream``s as parameter and return value.
